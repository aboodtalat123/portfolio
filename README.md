# TalatAI Portfolio V2

Bilingual ASP.NET Core 10 / Blazor static SSR portfolio with a personal assistant and the original Render Docker configuration. The six V2 case studies and assistant retrieve their public facts from `Editorial.cs`. The older case-study routes and project APIs remain available through EF Core and SQLite.

## Production-mode local preview

```powershell
dotnet test Portfolio.slnx -c Release
dotnet publish src/Portfolio.Web/Portfolio.Web.csproj -c Release -o tmp/published
$env:ASPNETCORE_ENVIRONMENT = 'Production'
Push-Location tmp/published
dotnet Portfolio.Web.dll --urls http://127.0.0.1:5185
Pop-Location
```

Visit `http://127.0.0.1:5185/` or add `?lang=ar`. The published app creates a local SQLite file. `/api/health` reports whether assistant configuration is present.

The browser suites require Python, Playwright browsers and PyMuPDF. Point `PORTFOLIO_TEST_URL` to the loopback preview and run `python tests/browser/experience.py` and `python tests/browser/assistant.py`. Run the suites against separate fresh preview processes to keep the fixed-window assistant rate-limit state isolated. Run `python tests/browser/engines.py --url http://127.0.0.1:5185 --engine webkit` for the WebKit smoke test.

## Assistant configuration

Use the server process environment. `.env.example` lists variable names. The application accepts `Gemini__ApiKey` and `Gemini__Model` or the existing `GEMINI_API_KEY` and `GEN_MODEL` names. Set a model verified for the dedicated project credential. `PortfolioAssistant__DailyRequestLimit` caps calls per process per UTC day. The browser receives streamed progress and a final reply. The server buffers Gemini events until it can validate the reply's citation IDs. A labeled portfolio excerpt is available when the model is unavailable, fails validation, or reaches its budget. Navigation is generated by an exact allowlist and requires user activation.

## Release

The existing Dockerfile publishes and runs the .NET app and uses Render's `PORT`. The configured readiness path is `/api/health`. Before production promotion, confirm the exact existing service and current production deploy ID, record the approved candidate commit, verify the dedicated provider through the intended service, and retain the previous healthy deploy for rollback. After promotion, check the original URL, health, mobile UI, download and real assistant responses. If a critical flow regresses, use the verified Render service's rollback to the recorded healthy deploy.
